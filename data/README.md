# HackMatrix — Data Layer

Three datasets powering the FIN04 insider-threat and money-laundering
detection pipeline. All synthetic HR/Access data is seeded from real account
IDs in the IBM AML dataset, ensuring 100% join connectivity.

---

## Dataset Inventory

### 1. IBM AML Transactions (`ibm_aml/`)

Real-world-scale synthetic bank transaction data from the
[IBM AML Kaggle dataset](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)
(HI-Small variant: High Illicit, Small).

| File | Rows | Columns | Description |
|------|------|---------|-------------|
| `HI-Small_Trans.csv` | 5,078,345 | 11 | Raw transactions |
| `transactions_clean.csv` | 5,078,345 | 11 | Cleaned, snake_case headers |
| `HI-Small_Patterns.txt` | 4,319 lines | — | Ground-truth laundering patterns |
| `SCHEMA.md` | — | — | Full column schema & sample preview |

**Key columns** (in `transactions_clean.csv`):

| Column | Type | Description |
|--------|------|-------------|
| `timestamp` | string | Transaction datetime (`YYYY/MM/DD HH:MM`) |
| `from_bank` | int | Sender bank ID |
| `from_account` | string | **Sender account ID** (primary join key) |
| `to_bank` | int | Receiver bank ID |
| `to_account` | string | **Receiver account ID** (primary join key) |
| `amount_received` | float | Amount received (in receiving currency) |
| `receiving_currency` | string | Currency of received amount |
| `amount_paid` | float | Amount paid (in payment currency) |
| `payment_currency` | string | Currency of payment |
| `payment_format` | string | Payment method (ACH, Wire, Credit Card, etc.) |
| `is_laundering` | int | Ground truth label: `1` = laundering, `0` = legitimate |

### 2. AMLSim (`amlsim/`)

Smaller-scale synthetic AML simulation data with explicit alert/pattern

| File | Rows | Columns | Description |
|------|------|---------|-------------|
| `accounts.csv` | 2,000 | 5 | Simulated bank accounts |
| `transactions.csv` | 8,297 | 8 | Simulated transactions |
| `alert_patterns.csv` | 52 | 8 | Suspicious pattern definitions |
| `alert_members.csv` | 337 | 3 | Accounts involved in each alert |
| `SCHEMA.md` | — | — | Full schema documentation |

---

### 3. Synthetic HR/Access (`synthetic_hr/`)

Employee, access-event, and profile-change data with hand-designed
suspicious and legitimate insider-threat scenarios. Account IDs are
sampled from the IBM AML `to_account` column for joinability.
Generated by `generate.py` (seed=42, fully reproducible).

| File | Rows | Columns | Description |
|------|------|---------|-------------|
| `employees.csv` | 200 | 6 | Employee roster |
| `access_events.csv` | 839 | 9 | System/account access logs |
| `profile_changes.csv` | 518 | 7 | Employee profile modifications |
| `employee_customer_map.csv` | 439 | 3 | Employee ↔ customer account relationships |
| `labeled_scenarios.csv` | 36 | 7 | Labeled scenarios (18 suspicious + 18 legitimate) |

## Join Keys

The datasets connect through account IDs:

```
IBM AML transactions_clean.csv
  ├── from_account ──┐
  └── to_account ────┤
                     │
Synthetic HR         │
  ├── access_events.csv         → target_account_id  ──→  from_account / to_account
  ├── profile_changes.csv       → customer_id         ──→  from_account / to_account
  ├── employee_customer_map.csv → customer_id         ──→  from_account / to_account
  └── labeled_scenarios.csv     → account_id          ──→  from_account / to_account
```

### Validated Join Rates

| Join | Match Rate |
|------|-----------|
| `access_events.target_account_id` ↔ IBM AML accounts | **100.0%** (838/838 unique, 839/839 rows) |
| `profile_changes.customer_id` ↔ IBM AML accounts | **100.0%** (518/518) |
| `employee_customer_map.customer_id` ↔ IBM AML accounts | **100.0%** (439/439) |
| `labeled_scenarios.account_id` ↔ IBM AML accounts | **100.0%** (39/39) |

## Validation

Run the cross-dataset join validation at any time:

```bash
python data/validate_joins.py
```

This checks file existence, row counts, and join match rates across all three
datasets.

---

## Regeneration

If you need to regenerate the synthetic data:

```bash
# Step 1: IBM AML cleaning (requires HI-Small_Trans.csv)
python data/ibm_aml/inspect_and_clean.py

# Step 2: AMLSim generation
python data/amlsim/generate_amlsim.py

# Step 3: Synthetic HR generation (requires transactions_clean.csv)
python data/synthetic_hr/generate.py

# Step 4: Validate all joins
python data/validate_joins.py
```

All generators use fixed random seeds for full reproducibility.
