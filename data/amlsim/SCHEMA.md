# AMLSim-Style Data — Schema Documentation

> **IMPORTANT**: This data was generated by a **custom Python generator implementing
> AMLSim's alert-pattern methodology** (`generate_amlsim.py`). It is NOT actual output
> from the IBM AMLSim Java simulator. The schema and pattern types are designed to match
> AMLSim's output format for downstream compatibility.
>
> Reference: https://github.com/IBM/AMLSim

## Generation Parameters

| Parameter | Value |
|-----------|-------|
| Random seed | 42 |
| Accounts | 2,000 |
| Simulation period | 45 days (2023-01-01 to 2023-02-14) |
| Normal transactions | 8,000 |
| Alert patterns | 52 total (12 cycle, 15 fan-out, 15 fan-in, 10 gather-scatter) |

---

## accounts.csv

Account metadata for all simulated accounts.

| Column | Type | Description |
|--------|------|-------------|
| `account_id` | string | Unique account identifier (format: `ACCT_XXXXX`) |
| `account_type` | string | One of: `individual`, `business`, `corporate` |
| `initial_balance` | float | Starting account balance (1,000 – 500,000) |
| `bank_id` | string | Bank identifier (`BANK_A` through `BANK_E`) |
| `is_sar` | int (0/1) | **Ground truth**: 1 if this account participates in any alert pattern |

---

## transactions.csv

All simulated transactions, sorted chronologically.

| Column | Type | Description |
|--------|------|-------------|
| `tx_id` | int | Unique transaction ID (chronologically assigned) |
| `from_id` | string | Sender account ID (references `accounts.account_id`) |
| `to_id` | string | Receiver account ID (references `accounts.account_id`) |
| `tx_type` | string | Transaction type: `TRANSFER`, `WIRE`, `CASH`, `CHECK`, `ACH` |
| `amount` | float | Transaction amount in USD |
| `timestamp` | datetime | Transaction timestamp (`YYYY-MM-DD HH:MM:SS`) |
| `is_sar` | int (0/1) | **Ground truth label**: 1 if this transaction is part of a suspicious alert pattern, 0 if normal |
| `alert_id` | string | If `is_sar=1`, the alert pattern ID this transaction belongs to (e.g., `ALERT_0001`). Empty string for normal transactions. |

### Ground Truth Label Columns

> **For testing rule-engine recall against known patterns, use these columns:**
>
> - **`is_sar`** (in both `transactions.csv` and `accounts.csv`): Binary flag indicating
>   whether the row is part of a known suspicious (SAR-worthy) pattern.
> - **`alert_id`** (in `transactions.csv`): Links each suspicious transaction to its
>   parent alert pattern in `alert_patterns.csv`, which provides the pattern type.
>
> To get the alert type for a transaction:
> ```
> transactions.alert_id → alert_patterns.alert_id → alert_patterns.alert_type
> ```

## alert_patterns.csv

Summary of each generated alert pattern (ground truth for pattern detection).

| Column | Type | Description |
|--------|------|-------------|
| `alert_id` | string | Unique alert identifier (format: `ALERT_XXXX`) |
| `alert_type` | string | **Pattern type**: `cycle`, `fan_out`, `fan_in`, or `gather_scatter` |
| `num_accounts` | int | Number of accounts involved in this pattern |
| `num_transactions` | int | Number of transactions generated for this pattern |
| `total_amount` | float | Sum of all transaction amounts in this pattern |
| `start_time` | datetime | Timestamp of the first transaction in the pattern |
| `end_time` | datetime | Timestamp of the last transaction in the pattern |
| `is_sar` | int (0/1) | Always 1 (all patterns are suspicious by design) |

### Alert Types Explained

| Type | Description | Typical ML Detection Signal |
|------|-------------|-----------------------------|
| `cycle` | A → B → C → ... → A. Money flows in a ring back to the originator. | Circular paths in transaction graph |
| `fan_out` | One hub account sends to many recipients. Distribution/placement. | High out-degree node in short timeframe |
| `fan_in` | Many accounts send to one hub account. Collection/consolidation. | High in-degree node in short timeframe |
| `gather_scatter` | Fan-in into hub, then fan-out from hub. Layering/structuring. | High in-degree followed by high out-degree on same node |

## alert_members.csv

Maps each account to its role within an alert pattern.

| Column | Type | Description |
|--------|------|-------------|
| `alert_id` | string | Alert pattern ID (references `alert_patterns.alert_id`) |
| `account_id` | string | Account ID (references `accounts.account_id`) |
| `role_in_pattern` | string | Role: `originator`, `intermediary`, `final_receiver`, `hub_sender`, `hub_receiver`, `receiver`, `sender`, `hub`, `gatherer`, `scatterer` |

```bash
cd data/amlsim/

```
